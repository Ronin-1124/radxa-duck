# Radxa Duck

基于 Radxa ZERO 3W 的小鸭子机器人项目，负责语音与视觉交互、云端模型接入、上层应用和管理网页。底层运动控制与整机硬件通过接口协作。

面向 Debian 12 / ARM64 / RK3566，使用 CPU Zipformer 识别语音、NPU 运行视觉模型。安装包包含应用、管理网页、Python 运行依赖和默认模型；依赖 Radxa 系统已配置的 HAT 音频、摄像头及 RKNN 2.3 系列运行环境。

从 GitHub Release 下载安装包及 `SHA256SUMS`，校验后安装：

```sh
sha256sum -c SHA256SUMS
sudo apt install ./radxa-duck_0.1.0_arm64.deb
```

安装后由 `radxa-duck.service` 常驻运行，浏览器访问 `http://板子地址:8765`。语音和视觉默认启用；网页离页或断连不停止大脑。网页预览与大脑采集分别控制，录音、图片和对话不长期保存。云端模型和角色身份在设置中配置，密钥只写入、不回传。

语音交互由云端理解后选择官方 Microduck 鸭叫音效回应，当前不使用 TTS。大脑日常获取本地检测摘要；明确要求观察时，才向支持图像的已配置云端模型发送单张当前画面。`/api/brain/context` 可只读查看角色、设备事实和可用能力，不包含密钥、录音、图片或完整会话。

运行配置为 `/etc/radxa-duck/config.json`，可调整能力启用策略、模型路径、访问来源和端口；修改后重启应用服务生效。显式关闭的能力在本次进程中保持关闭，服务重启后采用配置文件的启动策略。身份、云端配置及管理任务状态保存在 `/var/lib/radxa-duck`，卸载保留这些数据。系统内核、启动项、HAT 和 NPU 驱动由板端环境维护。

包内 `build-manifest.json` 记录模型、运行依赖的版本、来源及校验值；第三方声明随包保留。底层运动控制由独立运控服务提供，未接入时明确显示不可用。
